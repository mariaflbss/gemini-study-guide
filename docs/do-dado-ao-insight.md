# Do Dado ao Insight

## Entendendo minha vida acadêmica

Esta documentação acompanha o projeto interativo **Do Dado ao Insight — Entendendo minha vida acadêmica**, inspirado no tema da Semana 8 da jornada de Embaixadora Estudantil do Google.

## 1. Objetivo

O projeto demonstra que um insight não aparece simplesmente porque existem dados. É necessário começar por uma pergunta, preparar as informações, visualizar os registros, investigar padrões e explicitar os limites da conclusão.

O fluxo é:

**Pergunta → Coletar → Preparar → Visualizar → Descobrir → Insight → Limitações**

Os dados utilizados são fictícios e servem exclusivamente para demonstração.

## 2. Coletar

A primeira etapa apresenta uma tabela de registros acadêmicos. O objetivo é mostrar o dado antes de qualquer interpretação.

Entre os registros demonstrativos existem exemplos de duplicação, valores ausentes e um valor extremo de duração de estudo. Esses problemas não são escondidos porque fazem parte da própria investigação.

## 3. Preparar

Antes de criar gráficos, o projeto identifica problemas de qualidade:

- valores ausentes;
- registros duplicados;
- valores que exigem investigação por serem extremos.

A preparação não deve ser confundida com uma etapa puramente automática. Toda transformação precisa ter uma justificativa para que a análise posterior permaneça rastreável.

## 4. Visualizar

Os dados preparados são representados por gráficos simples. A visualização ajuda a perceber distribuição, concentração e diferenças entre registros.

Um gráfico, entretanto, não produz sozinho uma explicação causal. Ele é uma ferramenta para explorar o conjunto e formular perguntas melhores.

## 5. Descobrir padrões

O projeto apresenta padrões acompanhados dos registros que os sustentam. Um exemplo investiga produtividade em relação à duração do estudo. Outro compara atrasos com o prazo disponível.

A regra central é: **a evidência precisa aparecer junto do padrão**.

Isso impede que uma interpretação seja apresentada como se tivesse vindo de dados que não foram realmente observados.

## 6. Insight

O projeto separa:

- **Dado:** um registro observado.
- **Padrão:** uma regularidade encontrada em vários registros.
- **Insight:** uma interpretação útil sustentada por um padrão.
- **Hipótese:** uma explicação possível que ainda precisaria de investigação adicional.

Essa distinção reduz o risco de transformar uma observação pequena em uma conclusão geral.

## 7. Associação não é causalidade

Se dois fenômenos aparecem juntos, isso não significa que um causou o outro.

Por exemplo, observar que atrasos aparecem em registros com prazos curtos permite descrever uma associação no conjunto demonstrativo. Isso não permite concluir, sozinho, que prazo curto seja a causa de todos os atrasos ou que o comportamento se repita em qualquer população.

## 8. Limitações

A etapa final explicita o que não pode ser concluído a partir dos dados disponíveis.

Entre os limites do exemplo estão:

- conjunto pequeno e fictício;
- ausência de contexto suficiente para generalizações;
- possibilidade de variáveis não observadas;
- necessidade de novos dados para testar hipóteses causais.

Reconhecer limites faz parte da análise, não é uma falha da análise.

## 9. Relação com a Semana 8

A Semana 8 propôs utilizar o Gemini para organizar informações, identificar padrões, apoiar visualizações e transformar observações em aprendizados sustentados por evidências.

O projeto materializa essa lógica em uma experiência interativa que permite acompanhar o processo em vez de receber somente a conclusão final.

## 10. Conclusão

Uma análise responsável não termina quando aparece um gráfico. Ela termina quando a pergunta, os dados, a preparação, a evidência, a interpretação e as limitações conseguem ser explicados de forma coerente.
